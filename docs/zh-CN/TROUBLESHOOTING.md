# 故障排查与安全限制

## ESP32 无法上传

- 确认 USB 数据线支持数据传输，而不只是充电。
- 检查 Arduino IDE 中的开发板和串口选择。
- 关闭占用串口的其他程序。
- 如果需要按住 BOOT 才能进入下载模式，请按开发板说明操作。
- 先排除 USB 和开发板问题，不要一开始就改固件。

## 串口没有输出或乱码

- 将串口监视器设为 **115200 baud**。
- 选择正确的串口端口。
- 按复位键观察启动输出。
- 确认没有其他程序占用串口。

## 红外传感器读数不正确

- 使用 `i` 命令逐个检查传感器。
- 检查供电、共地、信号线和传感器高度。
- 用黑线和白底分别测试，确认模块输出极性。
- 避免强烈反光和环境光变化。
- IR1 已被记录为存在缺陷，但固件仍会读取；异常时应将其视为已知风险。

## 电机不转、方向错误或 ESP32 重启

- 先断电，检查电池电压、驱动板接线和电机端子。
- 确认 TB6612FNG 的 STBY 接 GPIO5，且逻辑电源和马达电源连接正确。
- 检查电源能否承受电机启动电流；电源压降可能造成复位。
- 确保 ESP32、驱动逻辑和传感器共地。
- 不要将电机直接连接到 ESP32 GPIO，也不要带电改线。

## ToF 读数异常或避障不起作用

- 检查 SDA=GPIO21、SCL=GPIO22、模块电源和逻辑电平。
- 发送 `v` 查看距离值。
- 确认目标位于传感器视野内，且传感器窗口无遮挡。
- 若初始化失败，当前固件可能禁用避障但继续循迹。因此机器人仍移动不代表避障正常。
- 查明问题前不要执行绕行测试。

## 机器人绕错方向或撞到障碍物

当前避障状态机依赖定时动作，并假设右侧空间可通行。它不会实时验证整条绕行路线。地面摩擦、电池电量、负载、电机差异和速度都会改变轨迹。

请降低速度，在空旷、封闭、无人且有急停手段的测试区验证。不要在楼梯、道路、人群或易损设备附近测试。

## 安全边界

- ESP32 GPIO 不耐受 5 V 输入。
- 电池与降压模块必须符合负载和电流要求。
- 首次测试时抬起车轮；测试避障时保持低速并随时准备断电。
- 项目文档不能替代实际硬件检查、风险评估和场地测试。
